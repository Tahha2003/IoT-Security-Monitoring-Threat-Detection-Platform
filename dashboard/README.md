# Dashboard — React Frontend

The real-time security operations dashboard for the IoT Threat Detection Platform. Built with React 18, it connects to the backend via WebSocket and REST API to display live threat intelligence, pipeline controls, SOAR management, and full alert history.

---

## Overview

The dashboard provides a complete operational picture of the IoT network's security posture. Every alert generated by the backend pipeline is pushed instantly over WebSocket — no polling, no page refresh. On first connect, the last 50 database alerts are replayed immediately so the feed is never empty even when no new traffic has arrived.

## Key Components

### `SystemControl.js`
Added in Session 2. Provides:
- **Pipeline Start/Stop** buttons — calls `POST /api/system/start` and `POST /api/system/stop`
- **NIC picker** dropdown — calls `GET /api/system/interfaces` to list backend network interfaces, lets user select the Zeek capture interface without knowing its name
- **Status pills** — PIPELINE / ZEEK / DATABASE / API — auto-refreshes every 4 seconds via `GET /api/system/status`
- **Log viewer** — dropdown to select log source, tails last N lines via `GET /api/system/logs/{service}`
- **DB Clear button** — calls `POST /api/system/clear-db`
- **Sudo setup button** — runs `setup_sudo.sh` via `POST /api/system/start?mode=sudo`

### `AllAlertsModal.js`
Added in Session 2. Opens over the Alert Feed when the user clicks "VIEW ALL →". Shows the full alert history with:
- Filters: severity, attack type, source IP
- All columns: timestamp, src/dst IP, dst port, protocol, attack type, risk score, severity, packet count, bytes, analyst verdict
- Calls `GET /api/alerts/all` with query params for each active filter

### `SoarPanel.js`
Added in Session 2. Shows:
- Toggle switch for each of the 4 playbooks — calls `POST /api/soar/playbooks/{name}` on change
- Recent automated playbook executions from `GET /api/soar/log`
- Manual **UNBLOCK** and **RELEASE** buttons for each quarantined/blocked IP

### `AnomalyGauge.js`
Rewritten in Session 3. Now a proper semicircular SVG gauge:
- Colour bands: 0–35% green, 35–60% yellow, 60–80% orange, 80–100% red
- Animated needle + hub circle
- Previous version had broken SVG arc math — fully replaced

### `AttackTimeline.js`
Rewritten in Session 3. Now an ECG/heartbeat-style SVG line:
- Continuous baseline with Q-R-S-T spike shapes on alert events
- Spikes colour-coded by severity
- Previous version was a standard bar chart — replaced to give a more intuitive real-time feel

### `NetworkTopology.js`
Rewritten in Session 3. Now an interactive live topology:
- Wired zone (Switch → Raspberry Pi, Backend PC, Kali Linux) and wireless zone (Router → Camera, BYOD)
- Animated packet flow dots along connection lines
- Threat links flash red when active alerts exist for a device
- Node detail panel on click — shows device IP, type, current status
- Zone labels use contrasting fill to be visible against background (previous version had invisible labels)
- Infrastructure node positions updated to avoid overflow

### `TopAttackers.js`
Updated in Sessions 3–4. Now filters out backend and infrastructure IPs from the leaderboard — only external/IoT attacker IPs are shown. `KNOWN` device label map updated to match real network IPs.

### `DevicesPanel.js`
Updated in Session 3. `KNOWN_DEVICES` map updated to real network IPs (192.168.50.x) from the previous hardcoded lab values.

## WebSocket

The `useWebSocket` hook in `src/hooks/useWebSocket.js`:
- Connects to `REACT_APP_WS_URL` (configured in `.env`)
- Auto-reconnects every 3 seconds on disconnect
- **On-connect replay:** the backend pushes the last 50 DB alerts immediately on connection — the Alert Feed, Anomaly Gauge, and Attack Timeline are populated instantly, not blank until new traffic arrives (fix added in Session 3)
- Incoming alerts are prepended to the alert list (capped at 500 in-memory entries)

## API Client (`src/services/api.js`)

All REST calls go through `api.js`. Base URL from `REACT_APP_API_URL`.

| Function | Method + Endpoint | Used by |
|----------|-------------------|---------|
| `fetchAlerts` | `GET /api/alerts` | StatsBar, AlertFeed |
| `fetchAllAlerts` | `GET /api/alerts/all` | AllAlertsModal |
| `submitVerdict` | `POST /api/review/{id}` | AllAlertsModal |
| `fetchPlaybookStatus` | `GET /api/soar/playbooks` | SoarPanel |
| `togglePlaybook` | `POST /api/soar/playbooks/{name}` | SoarPanel |
| `fetchSoarLog` | `GET /api/soar/log` | SoarPanel |
| `fetchQuarantined` | `GET /api/soar/quarantined` | SoarPanel, DevicesPanel |
| `unblockIP` | `POST /api/soar/unblock/{ip}` | SoarPanel |
| `fetchSystemStatus` | `GET /api/system/status` | SystemControl |
| `fetchInterfaces` | `GET /api/system/interfaces` | SystemControl NIC picker |
| `startPipeline` | `POST /api/system/start` | SystemControl |
| `stopPipeline` | `POST /api/system/stop` | SystemControl |
| `trainModels` | `POST /api/system/train` | SystemControl |
| `resetFirewall` | `POST /api/system/reset-firewall` | SystemControl |
| `clearDatabase` | `POST /api/system/clear-db` | SystemControl |
| `fetchLogs` | `GET /api/system/logs/{service}` | SystemControl log viewer |

## Configuration

Create `dashboard/.env` before running:

```env
REACT_APP_API_URL=http://192.168.2.101:8000
REACT_APP_WS_URL=ws://192.168.2.101:8000/ws
```

Replace `192.168.2.101` with the actual IP of your Backend PC. This file is gitignored — never commit `.env`.

## Setup & Running

### Install dependencies

```bash
cd dashboard
npm install
```

If the `react-scripts` symlink is broken:

```bash
chmod +x node_modules/.bin/react-scripts
ln -sf ../react-scripts/bin/react-scripts.js node_modules/.bin/react-scripts
```

### Development server

```bash
npm start
# Opens http://localhost:3000
```

### Production build

```bash
npm run build
# Output in dashboard/build/ — serve with nginx or any static host
```

## Connection Status

The header shows:
- **LIVE** (green dot) — WebSocket connected, real-time alerts streaming
- **OFFLINE** (red dot) — WebSocket disconnected, auto-retry every 3 seconds

The dashboard is fully functional in OFFLINE mode for historical data — only the live alert stream pauses.
